# 能力边界与版本决策索引

仅在判断能力取舍、模板升级、数据兼容、发布迁移或协作升级时读取。普通攻略制作不加载本文件；具体字段、页面、交互和迁移步骤以对应专项文档为准。

## 当前能力边界

| 类别 | 默认交付 | 条件启用 |
| --- | --- | --- |
| 内容生产 | 研究、文字版基础方案、`trip-request.json → trip-brief.json → trip-data.json → guide.html`、固定章节与资料来源 | 跨越中国大陆边境或国际/地区出入境时增加到达 / 离开专项研究 |
| 网页执行 | 响应式模板、逐日 Tab、搜索、资料索引、核验清单、ICS、当天地图与分段导航 | 图片、天气与汇率手动刷新、实际支出、彩蛋 |
| 地图 | 动态底图、地点、路线、方向及交通时间图层 | 中国大陆使用百度 JS API GL；境外或港澳台使用 Google Maps JavaScript API；密钥只读私有本地配置；用户要求时以 Pinbook 本地导出 My Maps KML |
| 协作 | 本地核验、搜索历史、地图视图与手动刷新结果 | 配置 Supabase 后共同编辑预定状态、执行备注、核验项和已识别机票信息 |
| 发布 | 最终 HTML 与必要相对资源 | 仅在用户明确要求上传或发布时执行远端操作；过程 JSON 留在本地 |

路线、日期、地点、逐日时间线、交通方案、预算基准、地图点位、差异化提示和资料来源只能修改 `trip-data.json` 后重新渲染。网页共同编辑只处理执行层状态。

## 变更决策

1. 先判定是内容填充、局部修复还是模板升级；单篇攻略例外默认不固化为全局规则。
2. 新功能若不属于现有条件模块，先评估固定章节、移动端、地图、搜索、协作与发布影响，再修改共享资产。
3. JSON 字段变化必须同步更新 schema、手写校验、渲染器和契约测试，不能只修改 HTML。
4. 协作或数据库变化必须明确迁移文件、执行顺序、用户是否需要在 Supabase SQL Editor 操作，以及未迁移时的降级行为。
5. 地图或外部 API 变化不得把密钥写入模板、可提交源 HTML、公开 Git 历史、文档或验证报告。Browser / Publishable Key 仅由私有配置或 CI Secret 注入，Secret / Service Role 永远不得进入浏览器。

- 修改单篇攻略时只读取对应内容、数据和增量规则，不因本文件存在而扩大验证或发布范围。

## 本地版本升级工具

模板升级使用 `node scripts/upgrade-skill.js --version=X.Y.Z`，统一 npm/模板版本、交互组合与锁文件。工具以旧锁为版本基线；同一未交付变更的修正可传 `--baseline-lock=<升级前本地锁副本>`，新版本仍必须高于该基线。不得为普通攻略内容修改更新模板锁。

锁文件 components 分别记录数据契约、页面、工具和最新数据库迁移。锁范围由 `locked-files.js` 枚举，覆盖全部运行资产、非测试脚本、SQL 和 Git hooks；漏列即失败。版本升级本身不等于验证通过，最后统一执行完整回归。

2.39.1：恢复常规小红书最低篇数硬门槛（见 research-and-sources.md）；当前由brief/content本地研究门禁执行，2.56.0起HTML不再用公开链接数量核验研究量。未登录提醒用户登录，既有不足篇数的数据须补齐才能重新生成，不得借补充阅读筛选降低研究门槛。

升级工具先在本地临时目录准备并验证完整结果，再替换版本文件与产物。正常异常会恢复已替换文件；升级前快照保留在输出的本地路径。断电或进程被强制终止不保证跨文件事务完成，可按快照恢复后重新校验。
