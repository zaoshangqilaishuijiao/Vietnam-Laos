# 网页生成、验收与发布

## 本地生成

`<skill-root>` 指已激活技能目录，不依赖当前工作目录。完整攻略按 [数据流水线](data-pipeline.md) 完成三份 JSON，通过模板锁后确定性渲染；局部修改按 [增量修改](incremental-changes.md) 保存本地基线、声明允许字段和冻结模块。只处理受影响内容，不重复无关研究。

页面结构见 [内容模块](content-modules.md)，交互见 [交互模块](interaction-modules.md)，静态核验见 [verification.md](verification.md)，日期依据见 [日期契约](date-coverage-contract.md)。默认 UTF-8 无 BOM，CSS/JS 内嵌、图片使用相对路径；不凭记忆填写外部资源 SRI。

页面只提供组件所需容器，不复制共享脚本生成的清单工具栏、导航或状态。全页只调用一次 `TravelGuideInteractions.initGuidePage()`。搜索、条件编辑和精确日期匹配的“今天”统一进入右下角牛哞组合工具，页面不得再建第二套固定入口。牛哞 WebP 是允许公开发布的模板资产，由渲染器写入攻略 `assets/`，公开构建按 HTML 预加载引用自动复制；素材失败时入口回退为 `…`。每个可选组件独立失败，不应阻断其余功能。

生成时先校验 HTML 与全部本地引用资源（含封面、行程参考图及运行素材），统一暂存后交付 HTML、资源与成功报告。正常写入异常时恢复已替换文件并输出失败报告；资源交付失败不能留下有效的成功报告。强制终止不保证跨文件事务，按本地快照恢复。冻结模块 restore 只用于差异诊断，不能交付与 JSON 不一致的页面。

私人 JSON、基线、研究笔记、浏览器证据和构建证明均只留本地。用户要求“生成网页”授权完成本地成品；只有明确“发布/上传”才执行远端动作。敏感操作遵循当前用户限制。

## 浏览器验收

静态验证通过后主动用真实浏览器检查，不把脚本生成的 passed 当成浏览器结果：

- 浏览器验收是 Agent 在发布流程中的执行步骤，不是新的授权点。用户已明确要求发布时，直接完成验收并继续发布，不先要求用户确认检查范围，也不在记录验收后再次询问是否提交。
- 自动化浏览器不能打开 `file://` 时，使用只监听 `127.0.0.1` 的临时 HTTP 服务验收同一产物；地图要求当前 HTTP 来源已获密钥授权，回环地址不被接受时才使用映射到本机的固定预览主机名。这不构成上传。不得仅因 `file://` 被限制就改为让用户逐项人工确认。
- `manual-attestation` 只用于浏览器自动化确实不可用且用户已经自行完成检查的兜底场景；最多一次性询问全部必要项目，不得拆成桌面、手机、地图、交互等多轮确认，也不得把用户一句笼统的“可以”伪造成逐项通过证据。

- 桌面、390px、412px：页面无横向溢出，文字、按钮和表单可用；宽表仅在自身容器滚动。启用并排布局时另测阈值前后。
- 控制台：无语法、资源路径、初始化错误。非核心外部失败须有明确降级。
- 地图：能加载时检查真实底图、Marker、路线、时间标签、跨日期定位和超时重试，状态记为 `passed`。地图因 Referer 拒绝加载时，先修正本地 HTTP 来源和白名单；只有修复不可行或服务端发生故障时，才检查降级路径并记为 `degraded`，整体验收为 `passed_with_limitations`，明确真实底图未验收。用户要求完整地图验收时，`degraded` 不满足完成条件。不能用 `file://` 验证 Referer。
- 交互：日期与导航、搜索定位、来源、复制、清单编辑及刷新恢复、图片、手动天气/汇率、原计划日历导出。协作启用时测试加入、保存、失败、退出。
- 封面保留完整视口照片、主题入口、编辑标题、路线摘要与三项旅程事实；不生成“查看行程／今日行程／继续上次”按钮，也不显示图片来源。进入行程统一使用正文快速导航和右下角组合工具。
- 新推荐卡的本地图片必须从 `trip-data.json` 同级相对路径复制到最终攻略目录，图片引用、作者及原帖链接随同一份公开页面交付；发布白名单从最终 HTML 的 `src` 自动推导，不能只推 HTML 而漏掉图片。封面仍不显示来源，推荐图片则在卡片内显示对应原帖作者和入口。

记录结果使用 `record-browser-qa.js`，不再只传检查项名称：

```bash
node "<skill-root>/scripts/record-browser-qa.js" guide.html \
  --validation=guide.validation.json --evidence=browser-results.json
```

证据 JSON 包含 `method`（`browser-run` 或明确的 `manual-attestation`）、`reviewer`、`checkedAt`、`sourceSha256`、`artifactSha256`、`assetSha256`，以及 `checks` 数组。每个条目包含 `name/status/evidence`，六项 name 为 desktop、mobile390、mobile412、console、map、interactions；evidence 记录实际测量或行为结果。地图的 `degraded` 仅用于外部密钥限制但降级路径已实际验收的情况，其他检查项仍须为 `passed`。哈希可由 `scripts/qa-evidence.js` 导出的 `sha256/assetDigest` 计算。不得把未做的检查写成 passed；人工签署明确标明方法，不伪装自动浏览器测试。

记录器会复核静态结果哈希和产物契约；刷新报告时间不能恢复过期结果。证据/截图保留本地，不上传私人内容。

## 公开源与部署产物

当前发布工具支持 **main 分支、仓库根目录 HTML**。不支持子目录攻略或其他部署分支，必须在提交前说明，不先推送后失败。

1. `render-guide.js trip-data.json guide.html --public-source` 生成公开源。保留协作时加 `--public-collaboration`，公开模式不读取本机真实协作配置。若旧版启用协作，关闭须先按用户决定处理，不能静默降级。
2. 将 `scripts/public-config.js` 导出的 DEPLOYMENT_FILES 全部复制到发布仓库（目前为 build-public-guide.js 和 public-config.js），并复制 `assets/github-pages-deploy.yml` 到 `.github/workflows/`。这些部署文件须与当前技能版本一致。
3. Repository Secrets 按需要配置 `GOOGLE_MAPS_BROWSER_KEY` 或 `BAIDU_MAP_BROWSER_AK`，协作使用 `SUPABASE_PROJECT_URL` 与 `SUPABASE_PUBLISHABLE_KEY`。仅 Browser/Publishable Key 可进入最终浏览器产物；service role/secret 永不进入浏览器。Browser Key 限制域名、API 与额度。
4. 本地验收公开源时，在被忽略的本地临时目录构建注入后的产物：`build-public-guide.js guide.html <private-preview>/guide.html --attest-build`；本地环境变量提供受限 Browser Key、所需协作公开配置及 GUIDE_BUILD_SHA。不得用无效占位值完成地图验收。证明写入产物旁的 `.build.json`，不包含配置明文。以 `--artifact=<private-preview>/guide.html` 登记验收，证据绑定公开源、实际产物和图片等资源。
5. 本地页面服务器只监听 `127.0.0.1`，优先通过获地图密钥授权的 `http://127.0.0.1:<端口>/guide.html` 打开本地产物。若服务商拒绝该来源，再将已授权的固定预览主机名在本机映射到 `127.0.0.1`，从 `http://<预览主机名>:<端口>/guide.html` 访问同一服务。真实底图、Marker、路线等地图内容加载正常，地图状态才记为 `passed`；否则先核对 Referer、API 和密钥配置，仍不可用时如实记为 `degraded`。此步骤不上传攻略，也不要求本地 HTTPS 证书。
6. 本地来源、必要时的 hosts/DNS 映射和 Browser Key 按 [地图与地理编码](map-and-geocoding.md) 配置。无效密钥不能作为地图通过的证据。
7. CI 对根目录每份 HTML 构建，上传 `_site` artifact；源文件保留占位符，构建结果不回写 Git。本次新增的目标页面必须完成验收，其他页面沿用已提交版本。

同一套受限 Browser Key 可供本地预览和正式 Pages 使用，无需重复创建密钥：在对应地图控制台允许正式 Pages 域名和实际使用的本地 HTTP 来源，并继续限制必要 API 和额度。本地构建只从私有配置注入，GitHub Actions 只从 Repository Secret 注入；不得为了本地验收移除 Referer/API/额度限制。

## 发布入口

```bash
node "<skill-root>/scripts/publish-checklist.js" <发布仓库> --repo=<发布仓库> --page=guide.html --check
# 当前任务已有明确发布指令时，完成浏览器验收后直接执行：
node "<skill-root>/scripts/publish-checklist.js" <发布仓库> --repo=<发布仓库> --page=guide.html --execute
```

`--check` 是审查或排障用的只读模式，不是 `--execute` 的强制前置步骤；`--execute` 会自行重复全部只读门禁。用户明确说“发布到线上”“上传”或“提交并推送”即为本次正常发布链路的一次完整授权，覆盖浏览器验收、白名单暂存、提交和推送。不要在 `--check` 后再问一次，也不要在浏览器验收记录后再问一次。只有以下情况暂停：需要用户登录或处理验证码；仓库/分支不明确；禁用邮箱或密钥门禁命中；页面验收失败需要修改；或动作超出正常发布范围且具有破坏性。

更新同一路径的已发布攻略时，发布门禁把新页面与仓库 `HEAD` 中上一版正式页面对照：要求渲染报告证明本次输入 JSON 已与上一版 JSON 按白名单比较，且 `--baseline-html` 的哈希等于该正式页面；上一版正式页面若含内容指纹，还要求基线 JSON 的指纹完全匹配。行程项、预定项、清单项、推荐项、来源 ID、图片或外部链接无说明消失时阻断。模板跨版本升级仍做 JSON 连续性检查，不冻结旧版 DOM。确实要删除的项目，在本次发布命令中逐项追加 `--allow-removed-ids=item:<id>,image:<src>`（按门禁输出的精确键填写，不支持通配）；只凭宽泛的 `--allow-paths=days` 不能默许项目消失。首次发布不要求旧页面证明。过程 JSON 与基线仍只留本地。

多页面目录必须通过 `--page=<文件名.html>` 明确本次发布对象；只有一个 HTML 时可自动选择，不按验收报告修改时间选页。优先从用户指定成品路径确定页面，不为已明确的对象重复询问。其他页面的独立未提交修改仅提示并留在本地；白名单外暂存仍阻断。若更新了其他已提交页面共用的资源，必须验证其已提交 HTML 与新资源组合，不能用另一份尚未提交 HTML 的验收代替。全部待推送提交的新增、修改、删除路径均须在本次发布白名单内；不因文件没有敏感词而放行，不自动拆分或改写历史。旧版无 guideId 的同路径页面仍须正式基线及稳定内容连续性证明。

只读检查核对静态哈希、浏览器源/资源绑定、实际引用白名单、部署依赖、暂存范围、待推送历史和实际 Git 作者/提交者。扫描真实密钥时精确排除合法占位符，Supabase 配置也不能进入公开源。过程 JSON、验证报告、基线、研究目录与私有配置禁止进入待推送历史，后续删除不能消除历史风险。已有明确发布指令时可以跳过单独运行 `--check`，直接使用 `--execute`，因为执行模式包含同一套检查。

发布仓库本地配置禁用邮箱域 `travelGuide.forbiddenEmailDomain` 和 `.githooks`。发布程序独立检查实际身份及历史身份，不依赖 hooks 是否生效；hooks 仍作为第二层保护。禁用组织邮箱的门禁不能跳过。

执行模式先刷新远端引用，再限定本次待推送提交范围；只读模式使用已有本地远端引用，不联网。扫描这些提交新增或修改的文本 blob，同一 SHA 在本次运行中只读取一次，提交后的复查复用该缓存。中间提交曾含配置而后续删除也会被阻断；不扫描远端已包含的历史，不引入跨次缓存或自动清理历史。

execute 一次完成预检、白名单暂存、提交和推送：提交前检查已有待推送历史，提交后只补查新提交及其实际作者/提交者，不重复扫描已检查的历史。白名单外本地目录不遍历、不上传。推送成功即完成本地发布动作；GitHub Pages workflow 在远端异步部署。工具不依赖 `gh`，不等待 Actions，不执行线上 HTTP、`guide-build` 或模板版本复核，也不因暂时尚未部署而重复提交或推送。

发布文件仅含最终公开源 HTML、真实相对引用资源和部署依赖。发布仓库的 `.gitignore` 应包含 `.private-preview/`，防止手工暂存时误收录注入配置的本地验收产物。未引用文件保持本地，不批量删除。CI 仍构建仓库内全部根目录页面，但未选中的页面采用已提交版本；只在共享资源受本次更新影响时补验收，不把本地其他页面的修改自动发布。

## 上下文与交付

默认不将整份生成 HTML 或完整增量 JSON 放入 AI 上下文；读取报告、定向片段和浏览器状态。基线是本地被忽略文件，不提交到任何分支。最终交付只说明成品路径、结构化数据路径、核验结果和确实未完成的外部步骤，不粘贴整份源码。
