# 研究、来源与隐私规则

## 使用时机

只要任务涉及目的地研究、路线规划、餐饮推荐、交通核验或资料来源，就读取本文件。


## 研究闭环（唯一权威）

研究必须同时满足“小红书最低篇数”和“信息足够支持决策”；所有篇数、专项边界和结束条件只在本节维护。

首次阅读先按下节在本地留存有用事实与素材，实际已读且纳入研究的来源写入 `trip-brief.json.researchSources`，实际读取数量写入 `researchAudit`，最终继承到 `trip-data.json.sources`。本地缓存条目数、查询命中数和图片数均不能当作已读篇数或核验完成证明。

## 首次读取留存与按需调用

每份攻略复用一份 `research.local.json` 和同目录 `research-assets/`，作为本次旅行的私有研究记录；用户已有文件先按需提取相关内容，不自动批量迁移、合并或删除旧文件。只保存本次确定会用的信息、有明显价值的候选，以及会改变已有判断的证据。留存不等于推荐、可用或公开发布；不保存整份工具返回、全部搜索结果、重复正文和无关评论。

首次读取小红书时同时查看正文和图集，当次保存有价值的实景图片文件。地点展示图使用能看清入口、环境、景观、菜品或商品的实拍，跳过标题封面、文字海报、拼图以及大字或贴纸遮住主体的照片。沿用 `assets[]`、`research-assets/` 与原帖、作者、地点／分店、图片序号关联。核对地点与画面后才标为可用。出行模式和推荐卡片按地点复用。缺图先查询已留存素材，再按需从其他笔记或官网补齐。菜单、路线指引和操作截图按实际用途留存。

| 模块／用途 | 首次遇到就留存的有用信息 |
| --- | --- |
| 封面与路线概览 | 代表性实景、图片实际地点／季节、城市间真实连接方式；标题根据最终路线原创生成 |
| 到达／离开 | 机场／航站楼、到达时段、签证与同行条件、实际通关分钟数、现场办理位置；单据填法另查官方原表 |
| 机场三件套 | 电话卡柜台位置、套餐／天数／流量／号码短信差别；具名柜台或 ATM 的报价方向、全部费用和日期；叫车点、公交线路与付款方式 |
| 逐日行程与交通 | 对应路段、入口／车站出口、换乘、门到门耗时、行李／通行条件、费用与观察日期，按下节逐段核验 |
| 附近逛逛与推荐 | 具体分店、区域、当地名称／别名、值得去的具体原因、能做什么、停留体验及对应照片 |
| 景点与体验 | 独特看点、入口、游览顺序、实际耗时、具体需预约的项目及执行条件 |
| 餐饮 | 具体分店、菜单照片、菜名、份量、观察价格、点单方式和口味体验；口味与客观事实分开 |
| 购物／夜市 | 商品实拍、当地名称、材质／工艺、摊区／店铺、辨认方法与观察价格；不凭营销词断言国内买不到 |
| 预订清单 | 官方预约入口、放票时间、时段选择、费用包含项、取消条件；用户订单和凭证仍单独留本地 |
| 预算／换汇 | 金额、币种、计价单位、人数、包含项、日期与适用卡种，防止把人均／整车或牌价／净到手混用 |
| 核验清单、APP与文化 | 真正需执行的动作；APP准确名称与影响使用的条件；具体场所服装、拍照、支付等规则。Logo仍查官方来源 |

跨模块同时留存最后一段路（入口、出口、楼层、码头侧别）、博主同行条件和行李、具体支付限制，以及会改变判断的作者补充／近期评论。评论证据标明评论 ID，与正文分开。误认分店、图片错配、停售、不可行路线等有用反向证据可保留为 `rejected`，默认查询不推荐它，防止后续再选回。原帖后续变化或不同日期报价应新增观察记录，不静默覆盖旧证据。

### 一份记录、四种关联

使用 `scripts/research-store.js` 保存和检索；无需给每个模块另建资料库，也不为模型读取整份 JSON：

- `sources[]`：`type/title/url/readAt`，小红书另有 `author`，可加 `publishedAt`。工具按实际长链自动生成 `xhs:<笔记ID>`；不同分享参数和入口仍是同一来源。其他网页使用规范 URL 的稳定标识。不接受未展开短链冒充已读。
- `entities[]`：稳定 `id/name/city/country`，按需添加 `localName/aliases/address/placeId`；同名不同分店各自建身份，已经核对对应地点库时关联 `placeId`，不复制一套运行时坐标。
- `facts[]`：`sourceId/entityIds/category/text/modules/dynamic/locator`，可填 `observedAt/conditions/state/id`。`modules` 引用现有章节名，例如 `itinerary/recommendations/bookings/budget/arrival`。一个事实被多处采用时增加引用，不复制事实。`locator` 用 `{kind:"body"}`、`{kind:"image",imageIndex:2}` 或 `{kind:"comment",commentId:"原评论ID"}`。`dynamic` 对价格、班次、营业、套餐、预约规则等填 true；达到可用状态的动态事实须有观察日期。
- `assets[]`：`sourceId/entityIds/kind/locator`，保存本地图片时传 `file`，工具复制到 `research-assets/<内容哈希>.<格式>`；相同图片只保存一个文件，不同来源／用途保留各自关联。实际查看后才设 `inspected:true` 并填 `description`（菜单、门脸、商品等具体对象），需要核对分店。可用素材设 `state:"usable"`；失败只记 `failure`，不造占位图片，不无限重试。

事实和素材默认 `candidate`，经本次判断才设 `usable`，需补查设 `recheck`，已排除设 `rejected`；保存时间不是观察日期，已读不是已核验。正文、评论和图片中的转录事实都需注明证据位置。修改既有事实时读取完整片段再写回；改变观察内容、日期或适用条件时使用新的事实 ID，保留冲突。工具不自动改动 `trip-data.json`、计数、预订状态或网页。

```bash
# 将刚读帖提取的来源、地点、事实和本地图片一次合并；patch本身也留本地
node scripts/research-store.js --store=<攻略目录>/research.local.json --merge=<本地提取片段.json>
# sourceId取第一次合并返回／查询中的稳定ID；小红书为xhs:<笔记ID>
node scripts/research-store.js --store=<攻略目录>/research.local.json --module=recommendations --city=万象 --limit=10
node scripts/research-store.js --store=<攻略目录>/research.local.json --entity=<地点ID> --category=menu
node scripts/research-store.js --store=<攻略目录>/research.local.json --module=itinerary --q=机场 --limit=10 --offset=10
# 图片独立翻页；下一页使用返回的 nextAssetOffset，直到 assetHasMore=false
node scripts/research-store.js --store=<攻略目录>/research.local.json --entity=<地点ID> --asset-limit=20 --asset-offset=20
```

合并输入只含需新增／更新的 `sources/entities/facts/assets` 数组，不用抄回全库；实体保留稳定身份，来源按笔记去重，同一观察跨模块引用去重。无效引用或冲突身份会拒绝写入；不会删除旧条目。图片文件未能留存时明确保留缺口，后续有实际需要再定向补查。

首次补齐缺图时，查询原素材完整记录，保留其id、sourceId、entityIds、kind和locator，增加file后合并；允许“无文件→首次有文件”，成功后清除已解决的failure。下载成功不自动设为已查看或可用，仍需实际核对后设置inspected/description/state。更换已有图片或改变来源、图片位置、地点／用途时仍用新ID，不覆盖原证据。

### 内部调用顺序

1. 写某模块前按城市、地点、类别、关键词查询；默认返回最多10条，可分页、最多50条。工具单次读取本地库并建立内存索引，优先使用较小候选集，联结相关来源、地点和素材；不输出整篇笔记、全量图片列表或完整工具返回。脚本内重复查询可复用 `createContext(loadStore(file),目录)`，无需重复解析或另存易漂移的索引文件。
   按source或entity直接查询时，不要求先提取facts：首次读帖保存的来源和素材也可返回；city和state继续参与筛选。模块、类别或q关键词查询则沿匹配事实关联素材，不因指定来源／地点而绕过事实筛选。total表示匹配事实数，不代表来源或素材数量；不要因total=0就重新抓取已保留素材。
2. 先核对查询返回的地点身份、证据位置、适用条件和日期。动态事实始终标记 `needsRecheck`，不设武断有效期，也不把它自动当作当前价格或班次；稳定地点、别名与已核对图片可复用，改变分店或现场条件仍需再核实。素材查询检查返回图片的文件存在及哈希，不把路径存在视作分店语义核实。
3. 只针对实际缺项补查，补齐后写回同一本地记录。事实用limit/offset，图片用asset-limit/asset-offset独立分页，单页均最多50；图片范围来自完整过滤结果，不随当前事实页变化。按assetHasMore/nextAssetOffset取后续页，不能反复读取第一批或用重搜代替翻页；只返回本页关联来源与地点。资料仍不足就在文字研究稿列缺口，不给网页增加泛化提醒，也不为填满模块继续抓取无价值信息。
4. 采用后填入现有 `trip-brief/trip-data` 契约：研究来源ID映射到已有稳定数字 `sources.id`，地点关联 `places.id`，菜单／商品／交通等进入原有字段。只有经选中的图片复制到成品 `images/` 等安全相对目录，沿用已有原帖归属和发布白名单；原始记录及研究图库不进入HTML或公开仓库。缓存中的候选、排除项、未核验图片不自动进入推荐。

旧攻略局部修改继续从最近确认的 `trip-data.json` 和基线出发；研究库只用于补充证据，不能以旧研究记录覆盖用户后续修改。没有研究库的旧攻略照常使用，不强制回迁；新研究按本方案渐进留存。

- 常规研究必须读取 10 篇及以上高相关、去重的小红书攻略。这是用户明确要求的硬性门槛；官方资料、决策覆盖表、受阻原因或用户登录困难均不能代替篇数。已合规攻略的局部修改可复用仍相关的已读来源，不必每次重读全部笔记。
- 到达/离开专项建议读取 3 篇，单独统计，不挤占上述 10 篇常规攻略。专项不足时记录原因和 decisionCoverage；动态事实仍需官方核验。
- 未登录时明确提醒用户在浏览器中登录小红书；在用户完成登录、确认笔记可见后继续低频读取。篇数不足时研究保持 pending 或 blocked，不得标记 completed 或交付完整攻略；可以继续不依赖登录的资料整理。
- 用户长期约束（2026-09-21）：后续审查、优化、重构和版本升级不得再次将“至少 10 篇小红书攻略”改为建议值、删除门槛或增加替代证据豁免；只有用户后续明确修改此要求时才能调整。
- 使用浏览器访问笔记保持低频、串行，不绕过平台限制。

| 决策面 | 必须覆盖 |
| --- | --- |
| 路线与日程 | 城市顺序、每日主目标、住宿地、体力与备选 |
| 交通与到离 | 跨城方式、关键窗口、机场 / 车站衔接、已核实运营限制 |
| 执行资源 | 重点景点、预约 / 停车 / 入口、用餐或休息安排 |
| 风险与预算 | 天气 / 道路 / 船期等风险，价格性质与预算口径 |
| 资料追溯 | 关键经验可定位到资料来源，动态结论有官方来源 |

### 逐段交通研究与推荐

首次阅读小红书就把会影响出行选择的经验保存在已有本地研究记录中：适用城市／区域／路段、时段、交通方式、上车点／车站／入口、换乘、费用、行李或通行限制，以及作者、原帖和观察日期。正文、截图中的有用信息一次留存；不额外建立永久台账，复用已读资料后再定向补查缺口。

逐段选择按以下顺序执行：

1. 用当地经验提出候选，确认是否适用于本次具体起终点和时段。某篇“当地摩托车方便”不能推出每段都选摩托车；其他酒店的车费或时间不能直接挪用。
2. 用地图和运营方资料核实路线、运营条件与门到门耗时，包含到站步行、候车、换乘及下车后步行；小红书提供实际体验和推荐理由，不能替代本段耗时核验。不得把纯车程与公共交通门到门时间混作同一口径，或把未核验等待时间伪装成精确数据。
3. 按总耗时、到达位置、换乘复杂度、费用、当天体力、行李、明确偏好和交通本身的体验价值筛选。临近街区可能只选步行；跨城区可能选轨道与打车；机场接驳看下一站、到达时段和行李；沿河或山地按实际加入渡船、索道等。已有地铁或叫车方案时，步行 1 小时 36 分钟通常省略。如果步行本身是当天的游览体验，可保留。按实际价值筛选，避免设置统一距离或时间阈值。
4. 保留有不同决策价值且有证据的方案，标记唯一推荐项。可以只有一种，不为了三类齐全补写，也不为多选而保留明显不合理或差异很小的方式。将选中方案写入对应到达条目的 `navigationOptions`，来源通过条目 `sourceIds` 引用，具体路线核验过程留在本地研究记录。网页只展示执行信息，确有影响行动的条件才加一句提示。

发布前按实际路段审阅选择质量和页面完整性：已选方式、各自耗时、推荐项、emoji 胶囊与导航须一致；不能以方案数量或方式齐全代替合理性判断。无充分依据时少推荐一种；研究缺口留在文字稿，不给页面增加“注意交通／看情况调整”等空话。时间线、地图默认驾车图层和日历计划仍各按原有契约，不因比较方案而自动重排。

### 现场可用性专项（新攻略）

机场落地三件套从实际已读小红书提取；证据、内容价值和缺项边界统一见 [机场落地三件套](content-modules.md#机场落地三件套)。读帖保留有用正文、价目表／位置图与作者原帖，图片价格需实际查看后才能采用；搜索摘要不算核实。报价标注观察日期，后于行程的帖子不能伪装成出行当时已知资料。

完成最低 10 篇去重小红书笔记后，继续按决策面补齐信息，不以篇数代替可用性：

- 补研究前先盘点本地已读来源和已用地点，按城市/日期检查推荐价值、具体分店、图片、坐标和动态信息的缺口；仅复用仍相关且已核验的证据，再定向搜索缺项。不要求额外建立一套永久台账，使用本地研究记录即可。区分“资料不足，尚不能确认”和“核对后不值得推荐”，不因复用而免除事实核验，也不把旧图片重复计为新读笔记。
- 每个最终推荐地点都记录具体推荐理由、适用的行程日与大致区域（必要时注明 A→B 路段）、核实坐标、一张与地点相符的图片及图片对应的已读笔记 ID/作者/原帖链接。夜市推荐须具体到冰箱贴、玩偶、手工艺品等商品及可寻找的区域，不写“值得逛、可以买特色纪念品”之类空话。
- 实际查看拟用图片，核对具体地点与分店：店招、环境、商品或入口是否对应；排行榜、宣传海报、同品牌其他分店不能冒充该店实景，商品照片也不能证明入口位置或整店环境。多门店笔记须确认所选照片归属；无法确认时换图或继续核验，不能仅凭文件存在、笔记标题或同品牌推定可用。来源可追溯不等于获得公开使用权，本地研究图不自动进入共享资产或发布白名单。
- 新攻略按 [附近逛逛策略](nearby-explore.md) 以特色、品质、独特性和用户兴趣筛选普通日 3–5 / 真正交通日 1–3 个候选，记录逐日状态；顺路加分但不作为资格条件，值得专程去的同样推荐，时间与距离用于解释取舍。候选可为咖啡店、早餐店、书店、公园、码头、特产店等，复用已研究地点与推荐卡，不凑数、不另造没有图片和原帖的薄资料。合理不显示日记录原因；道路缺段、没有原行程空隙或建议休息不直接阻断有价值的推荐。最低 10 篇已读笔记门槛保持不变。
- 餐厅优先记录官网菜单、餐厅公开菜单或可定位到原帖的菜单照片；Google Maps 评论可用于具体菜品体验的交叉核验，不把一条评论当作当前价格或营业承诺。只在证据足够时填写推荐菜、观察价格和观察日期。
- 换汇逐个记录具名 ATM/银行/兑换点、地点、观察日期、适用卡种或条件、当地币/CNY 汇率、固定手续费、比例费和当地币费用；用相同的人民币总支出计算净到手当地币。任一必要数字缺失则展示“数据不足，无法比较”，不能用中间价冒充实际换汇结果。渠道数字要能追溯到已读小红书笔记，动态数值只表述为观察值。
- 到达/离开优先找同机场及航站楼、相近到达时段、相同签证类型的亲历记录；分别记录入境排队时间和落地至出机场时间，不混写。没有可比条件或实测分钟数时不推算排队时长，不生成“提前三小时到机场”“注意排队”等通用提示。
- 到达/离开研究先确认本次护照、签证/免签条件、入境口岸与交通方式下是否实际需要填写入境卡、电子申报、海关申报或离境单据。需要时打开主管机关的现行原始页面/表格，逐项记录真实字段名称、应从哪份资料抄填、填写格式、提交入口与时点、适用条件及官方来源；只给填写方法，不保存旅客姓名、证件号码或申报答案。不适用的单据不生成卡片，无法核实字段或适用条件时在文字稿列为研究缺口，不编造通用填法。
- 按本次落地和旅行区域核对当地实际可用的 APP：优先解决机场进城、城市打车/叫车、外卖、火车票或公共交通、共享骑行等真实需求，不要求每类齐全。每个最终应用核对名称、适用国家/城市、具体用途、官方 Logo 与运营方原始资料；确认有影响安装或使用的条件才记录。已核实的官方页面/下载页可存入数据作追溯，但网页只提供点击复制名称，不生成下载按钮。Logo 在研究时本地留存，不能拿同名非官方图标、过期品牌图或无关城市版本替代。
- 先交付文字研究稿和字段缺口，再生成网页；旧攻略按用户要求局部修改时复用仍有效的已读来源，不强行补齐与修改无关的专项。

- 上表未覆盖时继续补证或删减无依据的承诺；缺口只在文字研究稿记录，不把“待核验”“另行落实”写进网页；不得用重复笔记凑数。
优先使用多个具体查询词获取高相关结果，但避免重复打开内容高度相似的笔记。

只有当评论区可能显著改变决策时才读取评论，例如：
- 实际排队情况；
- 隐藏交通限制；
- 近期踩坑；
- 地址或入口容易出错；
- 正文信息存在争议。

普通景点介绍、美食推荐和重复性体验无需默认展开评论区。

- 记录实际使用的重要来源即可，不要求保存所有搜索过程和无效候选。
- 记录查询词、实际成功读取数量、标题、作者、发布日期（如可见）、原始链接和可复用地点。
- 仅在评论可能显著影响决策时读取可见评论区。优先关注高赞、多人重复确认、作者回复，或包含地址、路线、营业时段、价格和避坑信息的评论；引用时单独标记为“小红书评论经验”。

## 反爬与登录拦截

遇到强制登录墙、验证码、403、地区限制、页面加载失败或评论无法展开时，立即停止并提示用户。不要绕过验证码、加大并发、持续更换请求参数或为凑足数量反复请求。兜底方式是请用户在现有浏览器会话中手动打开原始笔记；用户确认页面可见后，再低频、逐篇读取。

记录实际成功读取篇数、失败原因和实际可见范围。未成功打开的搜索结果只能作为候选线索，不能计入已阅读数量，也不能写成已核验事实。受阻后不自动反复访问；未登录时提醒用户登录，用户完成登录或解除拦截后再继续。未满足至少 10 篇时，不得以替代官方资料为由完成研究。

## 来源分级与核验

- 小红书只用于游客体验和地点线索，不能单独证明签证、法律、安全等级、开放时间、交通班次或价格。
- 动态或高风险信息必须使用政府、景区、铁路、航空、酒店或商户等官方来源复核。
- 同时记录信息来源、查询日期和核验状态；资料冲突时保留差异并优先采用较新的官方信息。
- 不把搜索摘要、聚合页面或模型记忆冒充已打开的原始来源。
- 研究依据的身份、核验用途和读取数量只在本地管理；是否进入网页按下节“补充阅读价值”独立筛选，不按平台或官方身份自动展示。

## 补充阅读筛选

核心规则：只展示值得用户点开继续阅读的内容。逐条回答“正文之外，用户还可获得哪些适用于本次旅行的具体信息？”已在正文完整写清的地址、营业时间、费用、交通耗时或操作说明，不用来源链接重复证明。

| 内容 | 选择标准 |
| --- | --- |
| 景点介绍、参观指南 | 有参观顺序、展览、历史文化、建筑特色等扩展内容才保留 |
| 街区玩法、美食、购物 | 有具体路线、选择依据或体验细节，能帮助继续探索才保留 |
| 完整操作教程、赛事指南 | 字段填写图例、关键步骤截图、复杂换乘出入口照片、赛道图、领物流程等可保留 |
| POI／坐标／地图搜索、普通线路图、点到点查询 | 不进入补充阅读；必要的具体方案进入行程，导航由既有地图入口承担 |
| 地址、联系方式、营业／票价／柜台／上车点核验、已定航班查询 | 实用事实写进正文；无额外阅读价值不展示来源 |
| APP商店页、Logo来源、基础介绍 | 只留本地证据；不进入补充阅读，既有APP名称复制交互保持不变，不新增下载按钮 |
| 薄图片帖、标签帖、打卡帖 | 无具体玩法或补充信息不入选；图片署名和原帖链接仍可随图保留 |
| 与当前方案无关、同主题重复资料 | 清理失去用途的链接；优先一篇完整清晰的资料，只有不同且有用的补充才另留 |

官方地址页不自动保留，小红书详实教程也不因平台身份自动保留。酒店、电话卡、交通或景点变化后重审相关资料。去重按阅读主题与增量内容判断，不只按URL；没有展示数量目标，可为零。

正文必须足够直接执行：营业时间、费用、预约方式、乘车站点、出入口、操作步骤照实写清。关键步骤需要截图时放在对应正文；不能删除链接后把正文缩成关键词，也不能要求用户多次跳转才能完成一个动作。不得为保留来源反向删减正文或虚构补充价值。

### 数据与渲染边界

- 私有 `research.local.json`、brief.researchSources、content.sources 与 researchAudit 保留研究依据；至少10篇去重小红书仍由JSON研究／生成门禁核验，不以网页链接数推断，也不减少实际研究量。
- 在 `trip-data.json.sources[]` 为通过筛选的资料增加可选 `reading:{topic,title,value}`。topic 从“景点与文化、街区玩法、美食购物、实用教程、赛事资料”选择；title 说明点开能看什么，value 具体说明正文之外的阅读收益。不入选省略 reading；旧数据缺少 reading 默认不公开，不推断其价值，不自动修改旧JSON。
- `sources.id/sourceIds` 继续是本地证据关联，不为清理网页删除研究依据或重排内部ID。现有 sourceIndex 可作为本地检索信息保留，但不要求每篇已读建立网页索引；输出从入选资料投影一次，优先复用标签与提示词，缺少时使用标题、用途和阅读收益，不凑标签数量。
- 增量兼容判断区分研究证据与展示元数据：只增删或修改reading不视为来源证据变化；URL、核验结论、作者、日期等事实字段变化仍重新检查，不能用阅读文案修改豁免真实证据变更。
- 渲染只对入选条目生成连续公开编号、正文角标和高级搜索索引；未入选的正文角标不输出。标题和说明均转义。无条目时隐藏栏目、禁用高级搜索，不展示空清单或泛化提示。研究正文、核验状态、未选来源及本地路径不得嵌入HTML或公开提交；图片旁必要的作者／原帖归属独立保留。
- 导航、地图、预约与填表等操作入口不属于补充阅读，不随清理移除。图注链接不要求在补充阅读重复登记。
- 每次重渲统一生成列表、编号、引用和搜索结果，禁止只手工删HTML列表。自动验收检查断引用、连续编号与索引指向；编辑验收检查链接是否有额外阅读价值、正文能否直接执行、重复和过期资料是否已清理。自动校验不能判断网页真实内容的阅读价值，也不能单凭HTML证明私有研究篇数。

## 来源数据与网页门禁

`sources.id` 在本地数据中仍从1连续递增且唯一；公开编号由补充阅读投影独立生成，不让每组从1重计。小红书已读来源保存实际打开后的 `xiaohongshu.com/explore/<note_id>` 或 `/search_result/<note_id>` 长链，按笔记ID去重；分享参数与不同入口不重复计数。`xhslink.com` 只作待打开线索，不猜ID或联网批量展开；成功打开后保留最终长链和访问参数，未能打开不算已读。入选阅读及图片归属继续复用既有小红书移动端跳转。

常规与到达／离开专项在私有JSON分别统计，不重复计数。JSON门禁拒绝常规不足10篇，ShortfallReason不能豁免。HTML只校验公开阅读的引用和结构，不再要求小红书分组、公开研究计数或十个链接；统计不替代事实核验，公开HTML也不作为私有研究证据库。

## 本地资料与隐私

- 只读取任务所需的本地文件，并记录实际使用的文件、资料类型和更新时间。
- 不把私人资料上传到搜索、地理编码、代码托管或其他第三方服务。
- 公开发布前检查姓名、手机号、住址、订单号、住宿门牌、账号、文件名、本地路径、图片元数据和提交记录。
- 不静默覆盖用户已确认安排；冲突信息保留差异并提示用户。
