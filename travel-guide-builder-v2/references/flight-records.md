# 已购机票记录

当完整攻略启用“到达 / 离开”时，在该章节显示紧凑机票卡；它不是独立主章节，也不进入导航。

## 录入方式

- 模块名称为“已购机票”，录入区默认收起。模块右上角只有一个统一入口：无记录时显示“录入凭证”，有记录时显示“管理凭证”。
- 表单只保留“上传机票图片”和“购票软件链接”两项；链接仅接受 `https://`。不展示航班号、航司、日期、机场、起降时间等手工字段表格。
- 上传图片后仅在本机识别，识别结果用于生成卡片；不得把不同航段的机场、日期或时间混合。无法识别的信息不编造，也不以恢复手工字段表格作为默认处理方式。
- 管理区不显示逐份凭证列表，不提供“新增凭证”或“删除凭证”入口。重新上传图片或提交新链接，保存成功后整组覆盖当前机票记录；不追加历史凭证。只提交新链接时不沿用旧图片及旧航班信息；需要同时保留图片和链接时，本次一并提供。
- 新内容保存失败或用户取消时，保留原有记录；保存成功后清理不再使用的旧图片。管理区提示覆盖行为，但不增加逐条管理步骤。
- 图片保存在当前浏览器 IndexedDB，绝不上传。启用共同编辑时，已识别的航班执行信息与购票链接可同步；无法识别完整航班信息的凭证仅保存在本机。同步不自动改变路线、地图、预算或 ICS。
- 不保存姓名、证件、订单号、票号、PNR、二维码、条码或 OCR 全文。此限制也适用于持久化图片：图片须脱敏后保存，含上述敏感信息的原图不得直接落库。
- 图片上传后提供本地遮盖和确认步骤，仅将用户确认后的重新编码图片交给识别与存储；不宣称自动识别并完整移除全部敏感信息。OCR 使用版本锁定的公开 jsDelivr 包与 WASM，只处理已确认脱敏的图片；不得把 OCR 依赖改为浮动版本。识别超时后恢复表单，可重试或仅保存脱敏图片。

## 录入后的显示

- 一张图片识别出多个航段时，按航段拆成多张机票卡。
- 仅在无记录时显示空状态“尚未录入机票凭证”；生成卡片后不再显示空状态。
- 卡片内不出现“添加机票凭证”或其他新增入口。
- 有图片时卡片可提供“查看图片”，以页内浮层打开。最外层卡片不显示“打开购票链接”；此按钮仅放在展开后的管理区，同一链接不按航段重复展示，在新窗口打开。
- 图片和链接可同时存在，但各自入口遵循上述位置。普通本机记录两者都没有时不生成可用卡片；来自共同编辑的完整航班信息可独立显示，当前设备没有图片时不显示图片按钮，不伪造凭证或“已核验”状态。

## 机票卡片内容

卡片仅展示执行信息，按以下顺序组织：

1. 第一行：去程 / 返程（或第几程）＋ 日期。
2. 第二行：航司、航班号、飞行时长。
3. 第三行：座位号、登机口、行李提取转盘；仅展示已有信息，整行无信息时省略。
4. 主信息行：出发时间与机场 → 到达时间与机场。
5. 中转提醒：仅凭证明确中转时，在对应前一航段卡片最底部（图片入口之后）显示“中转提醒 · 中转机场 · 停留时长”。字段不足时标记待核验；不因机场重合、航段相邻或时间间隔自动判定中转，不把去返程连成中转。直飞或没有明确中转信息时不显示此行。

- 机场优先展示“三字码 + 中文机场名 + 航站楼”。跨日航段须清楚区分起飞与到达日期，不把到达日期默认写成出发日期。
- 飞行时长仅使用已知信息或具有明确时区依据的计算结果，不直接用两地当地时钟相减。缺失内容不编造。
- 不展示餐食、机型、行李额度、行李说明、广告或自由备注等无关内容；行李提取转盘和中转提醒属于允许展示的执行信息。中转时长仅使用凭证明确标注的数值，不自动相减或推算；不臆测换机场、重新托运或入境要求。

中转采用可选 `connection: { airportCode?, airport?, durationMinutes? }`，存在该对象表示已明确中转，关联当前航段到达后的衔接；只保存机场与停留分钟数，不保存中转备注原文。旧记录没有该字段时保持原显示，需重新录入图片后才能识别其中的中转信息；不扫描旧图片、不迁移数据库。

## 卡片排布

- 以模块容器宽度为准：达到 720px 时固定两列、等宽、撑满整行；第 3、4 张自然进入下一行，形成 2×2 排列。小于 720px 时单列。
- 卡片内部为“起点—箭头—终点”三段式，时间突出、机场信息次级。航司及机场名称正常换行，不得被逐字挤成竖排。
- 航司与航班号组成左侧信息组，飞行时长靠右；长航司名称在信息组内自然换行。座位、登机口、转盘按实际已有项目等分一行，标签弱化、数值突出，以细分隔线与航班信息区分；转盘的完整含义保留在提示文字中。窄屏允许单项内换行，不挤占相邻项目。
- 卡片间距紧凑，使用现有青色主题及 `--guide-primary-*` 变量；不使用米色或额外状态卡。

## DOM 与初始化

页面声明 `flight-records`，并在 arrival 内仅输出一个 `[data-flight-records]`。使用 `[data-flight-manage]`、按需展开的 `[data-flight-editor]`、`[data-flight-list]`、`[data-flight-viewer]` 与 `[data-flight-seed]`，由统一入口初始化：

```js
TravelGuideInteractions.initGuidePage({ flights: true });
```

## 共同编辑同步

- 仅在页面已经进入共同编辑模式时同步；未配置 Supabase 或保持只读时，模块继续离线可用。
- 服务器保存航班号、航司、日期与时间、机场与航站楼、已知的座位/登机口/转盘/中转信息及安全的 HTTPS 购票链接；不保存图片、图片键、OCR 全文、订单号、票号、PNR、乘机人或证件信息。
- 保存凭证后以该次录入生成的航段组覆盖共同编辑中的旧航班信息。服务端数据是共同编辑的共享来源；收到其他设备更新时回写卡片，并保留当前设备同一航段的本地图片（如有）。尚未同步且远端不存在的本机航段必须保留在本机，并明确提示其未同步；不得静默丢弃或伪装为共享记录。
- 共同编辑数据库需执行 `005_flight_records_sync.sql` 并将 `guide_flight_records` 加入 Realtime；未执行迁移时，页面必须给出明确同步失败提示，不能宣称已同步。
- 机票整组保存复用全局保存队列、失败重试、关闭提醒和退出前等待；页面隐藏或退出时保存请求使用浏览器 `keepalive` 尽力完成，但网络中断仍可能失败，未完成时不得显示全局“已同步”。识别结果不完整时不以部分航段覆盖共享记录。
- 实时读取期间的新通知必须在读取完成后补查；本机有待保存机票时不得被旧远端响应覆盖。去返程标签及航段顺序必须保留，退出共同编辑后停止订阅并丢弃未完成的旧响应。
- HTTPS链接的路径、查询参数、片段与嵌套编码均须检查敏感信息；不允许登录凭据或含PNR、证件、订单标识等内容的链接。
